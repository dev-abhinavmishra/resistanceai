Everything about this project in one file. Updated 2026-10-17 after the

## 1. What this is

- **ResistanceAI** — a clinical decision-support prototype ("Molecular Tumor
  Board decision support") built by **Abhinav Mishra** for the
  **Congressional App Challenge**. Python + Streamlit.
- It predicts the **calibrated probability of treatment failure / early
  progression** on a cancer patient's first post-sequencing regimen, from
  the tumor's genomic + clinical profile.
- Trained on **real public MSK data** (MSK-IMPACT 2017 + MSK-CHORD 2024):
  35,286 sequenced patients ingested, **26,064 labeled** for training.
- **Investigational/research prototype** — not a diagnostic device; every
  screen carries the regulatory disclaimer strip.
- **Live public demo:** https://resistanceai.streamlit.app (works because
  the host mounts the licensed artifacts privately — see §12).
- Video/pitch deck: `ResistanceAI_Presentation_v9.pptx` (14 slides,
  generated by `deck/build_deck.py`).

## 3. Data pipeline (fetch -> ingest -> train)

### 3.1 Sources and licenses

| Source | N | License | Status |
|---|---|---|---|
| MSK-IMPACT 2017 (Zehir, Nat Med) | 10,336 samples | ODbL | in git, `msk_impact_2017/` |
| MSK-CHORD 2024 (Jee, Nature, PMID 39506116) | 24,954 patients / 25,040 tumors (24,950 ingested) | **CC BY-NC-ND** | `msk_chord_2024/` gitignored |

- CHORD clinical/sample/timeline TSVs came from the cBioPortal datahub
  GitHub mirror (manual download). Mutations + SVs were fetched by
  `backend/models/fetch_chord_api.py` via the public cBioPortal REST API
  (`/mutations/fetch` batched 2000 samples/request with 4 retries,
  `/structural-variant/fetch` restricted to ~24 fusion-relevant Entrez
  genes → `sv_count`/`fusions` undercount total SV burden for CHORD —
  documented asymmetry, treat as fusion-centric).
- Leftover exploratory payloads live in `msk_chord_2024/mut_*.json`
  (mut_body.json, mut_s500/s2000.json etc.) — harmless fetch artifacts.

### 3.2 `ingest_v2.py` -> `backend/data/patient_records.jsonl`

One JSON record per patient:

```
patient_id, sample_id, cohort ("impact2017"|"chord"),
clinical_input { age_at_diagnosis, sex, smoking_history, cancer_type,
  cancer_type_canonical, cancer_type_detailed, oncotree_code, stage,
  sample_type, metastatic_site, n_met_sites, tumor_purity, tmb, msi_score,
  msi_type, pdl1_status, gene_mutations[], mutation_details[], n_mut,
  n_indel_frac, substitution_spectrum{}, cna{}, fga, n_amp, n_deepdel,
  sv_count, fusions[] },
display { variants[≤12], cna_events[≤15], fusions[≤10] },
os_months, os_status, resistant (0|1|null), label_source ("tx"|"os"|null),
tx_agents[]
```

Details worth remembering:

- **One sample per patient**: `_pick_primary_sample` prefers the
  highest-purity draw; earliest SAMPLE_ID breaks ties (T01 sorts first).
- **Mutations**: nonsynonymous classes only (NONSYNONYMOUS set incl.
  cBioPortal `Variant_Classification` and VEP-style `Consequence` terms);
  `gene_mutations` capped at 60/sample, driver genes first; `display`
  keeps top 12.
- **Substitution spectrum**: 6-class collapsed (complements merged),
  keys C>T C>A C>G T>A T>C T>G.
- **CNA**: per-gene call dict retained only for flagged genes
  (CNA_FLAG_GENES ∪ HRD_GENES ∪ {CD274, RSPO3, NRG1}); fga = fraction of
  genes |call|≥1; n_amp = calls≥2; n_deepdel = calls≤-2.
- **SV/fusions**: counts + {gene1,gene2,sv_class} pairs; one-sided
  rearrangements legitimately have only gene1.
- **Stage mapping**: CHORD `STAGE_HIGHEST_RECORDED` is a 3-way bucket →
  "Stage 4"→"IV", "Stage 1-3"→"STAGE 1-3" (feature ord 4 and 2). IMPACT
  has no stage → `SAMPLE_TYPE` metastasis→"IV" else "II".
- **CHORD labels (real treatment outcome)**: first post-sequencing
  treatment t0 (timeline START_DATE ≥ -60). `resistant=1` if NLP
  progression event within t0-30d … t0+365d, or death ≤18 mo; `=0` if
  alive/no progression (or death ≥18 mo); censored→null. Patients without
  treatment data fall back to **OS proxy**: died <24 mo → 1, living ≥24
  mo → 0, else censored. `label_source` records which path.
- Also writes `cohort_index.csv` (per-patient index for quick analytics).

### 3.3 Patient identity — the uid gotcha

IMPACT and CHORD **share the `P-XXXXXXX` namespace**: 4,272 patient ids
and 4,201 sample ids collide and refer to different people (41 with
different cancer types). Every consumer must key on the cohort-qualified
uid `"<cohort>:<patient_id>"` (`corpus.record_uid`, sample variant
`record_sample_uid`). `feature_matrix.parquet` carries a `uid` column for
this. Bare ids: honored only when unambiguous (`_bare_index`); colliding
bare ids return None → fall back to the marked mock demo patient. Never
join on bare patient_id.

## 4. Feature schema (`backend/features.py`, 201 features)

`FEATURE_NAMES` = NUMERIC (30) + BINARY (~152) + cancer-type one-hots (19):

- **Numeric**: age_at_diagnosis, tmb_log (log1p), n_mut, 6 substitution
  fractions (frac_ct/ca/cg/tc/ta/tg), n_indel_frac, fga, n_amp,
  n_deepdel, sv_count, tumor_purity, msi_score, stage_ord, is_metastatic,
  sex_male, smoking_ever, driver_alt_count, + 10 pathway_* scores
  (rtk_ras, pi3k_mtor, cell_cycle, ddr_hrd, tp53, wnt, notch, chromatin,
  immune_evasion, hormone — each = fraction of pathway genes altered).
- **Binary**: `mut_<gene>` for ~110 DRIVER_GENES; `cna_<gene>_{amp,del}`
  for CNA_FLAG_GENES (amp≥2, del≤-2); fusion_any, fusion_rtk (partner in
  FUSION_GENES); hrd_present, mmr_deficient, pole_mut, msi_unstable,
  immune_evasion_alt.
- **Categorical**: `ct_<canon>` × 19 CANONICAL_TYPES (lung, breast,
  colorectal, prostate, ovarian, melanoma, pancreatic, bladder, renal,
  cns, esophagogastric, endometrial, sarcoma, head_neck, hepatobiliary,
  thyroid, cervical, mesothelioma, other).

Normalization subtleties (`normalize_clinical_input` — every model-facing
consumer MUST run inputs through it):

- Legacy v8 fields auto-map: `tmb_level` (tmb_1..4 → 3/7.5/15/30),
  `ct_transition_pct` (0-100 → `spectrum_fractions` fraction, not count),
  `structural_variant_burden` ("high"→ n_amp 8/n_deepdel 6/sv 15).
- `detected_variants` labels → real events via LEGACY_VARIANT_MAP
  (HER2+ → ERBB2 amp; PTEN_Loss → PTEN del; BRAF-V600E → BRAF mutation;
  EML4-ALK → fusion; MSI-H/TMB-H/HRD_Positive → flags, never genes).
  `_AA_CHANGE_RE` decides protein-label vs fusion-pair; `_NON_GENE_TOKENS`
  and `_CNA_SUFFIXES` prevent misparse (MYC_AMP → CNA, not fusion).
- MSI spelling family: corpus ships "Instable"; reports send MSI-H/MSS/
  Unstable/Stable/Low — `is_msi_unstable`/`normalize_msi_type` share one
  family so train/serve match. Unknown → None (falls back to MMR/POLE+TMB
  evidence).
- `smoking_ever` uses TOKEN matching ("ever" is a substring of "never" —
  a substring check would code every never-smoker as a smoker and miss
  CHORD's "Prev/Curr Smoker").
- stage_ord map: I=1, II=2, III=3, IV=4, "STAGE 1-3"=2, "STAGE 4"=4.
- is_metastatic = sample_type contains "metast" OR stage IV/STAGE 4.
- Spectrum precedence: substitution_spectrum counts → spectrum_fractions
  → population medians. `medians` come from the TRAIN split only and are
  baked into every vector (no train/serve skew, no eval leakage).

## 5. Model (`backend/models/train_v2.py`)

- **Architecture**: bagged ensemble of 8 `HistGradientBoostingClassifier`
  (params: max_iter=450, lr=0.05, max_leaf_nodes=31, min_samples_leaf=60,
  l2=1.0, early_stopping val_frac=0.12 n_iter_no_change=30). Each model =
  85% bootstrap resample of train, seeds 100..107. All 8 hit 450 iters.
- **Split**: labeled 26,064 → stratified train 15,638 / cal 5,213 /
  test 5,213 (60/20/20 via two train_test_split calls, random_state=42).
- **Calibration**: `IsotonicRegression(y_min=0.001, y_max=0.999,
  out_of_bounds="clip")` fit on ensemble mean over the CAL split only.
- **Percentile reference**: `cohort_risk` = sorted calibrated TEST-set
  predictions — a new patient's percentile is read against scores the
  model never trained on.
- **Honest KM strata**: risk-quartile survival curves use 5-fold
  out-of-fold predictions (no patient scored by a model that saw them).
- **Permutation importance** computed on held-out data, model[0],
  n_repeats=4.
- **Artifact** `resistance_model_v2.pkl` keys: feature_names, medians,
  models[8], isotonic, cohort_risk, meta {version "v9", label_rate
  0.5988, n_training 26064, cohort_risk_source "held_out_test",
  cohort_risk_n 5213, sklearn_version "1.9.1"}.

## 7. Inference (`backend/predictor.py`)

`predict_resistance(clinical_input)` flow:

1. `normalize_clinical_input` → `build_model_vector` (train medians).
2. 8 models vote on the 1-row matrix; mean → isotonic → `risk_score =
   int(round(proba*100))`.
3. **Ensemble-spread interval**: `ci_half = max(2, round(1.645 *
   std(votes) * 100))` → `risk_ci = [score±half]` clipped to 0-100.
   Documented as a disagreement proxy, NOT a calibrated coverage interval.
4. `cohort_percentile` = searchsorted into `cohort_risk`.
5. `mechanisms` = `mechanisms.analyze` (§8).
6. `feature_contributions` = **leave-one-out ablation**: each active
   feature reverted to 0 (binary) or its train median (numeric), batched
   into one predict call; weight = raw ensemble mean − ablated mean;
   top 12 by |weight|, display names via `feature_display_name`.
7. `_match_therapies`: site KB + universal biomarkers (NTRK/RET/NRG1
   fusion, MSI-H, TMB-H≥10, POLE+tmb≥40, HER2 amp/IHC3, BRAF **V600** —
   protein-change verified via mutation_details/variant_hints so class
   II/III BRAF don't false-trigger). Max 8 hits; none → "Institutional
   Standard of Care" card.
8. `_interpret` tiers: ≥70 HIGH / ≥40 MODERATE / else LOW, with
   plain-language sentence.
- `threadpool_limits(1)` wraps every predict — HGB OpenMP-parallelizes
  even single rows and thread dispatch costs exceed the kernel at ≤~50
  rows (the "serial-threaded inference fix" commit).
- Singleton `get_predictor()`; sklearn major/minor mismatch → warning.

## 8. Mechanisms engine (`backend/mechanisms.py`)

Curated rule engine (NOT learned): 20 rules with AND-ed `when` keys —
`genes` (all present), `genes_all`, `genes_any`, `genes_driver` (mut or
fusion partner), `cna_amp`, `cna_del`, `sites`, `min_tmb`. Each hit
returns mechanism, category, implication, strategy, evidence[] (auto-cited
per matched gene), level (established/emerging/hypothesis → confidence
high/moderate), sensitivity flag. Sorted sensitivity-last then by level.

Categories: Bypass track (MET/HER2/RAS/PI3K/FGFR/MAP2K/BRAF-amp/ALK+TP53/
KRAS-G12C-RTK), On-target/reactivation (ESR1, RB1→CDK4/6i, AR, SCLC→MAPK),
Lineage transformation (SCLC RB1+TP53; neuroendocrine prostate),
Immune exclusion (STK11/KEAP1, WNT, B2M/JAK1/2, PTEN-EMT), Drug-class
context (**sensitivity**: HRD→PARP, MSI-H/POLE→checkpoint),
Adaptive.

## 9. Digital twins (`backend/digital_twin.py`)

- Similarity over the **genomic subspace** only: TWIN_FEATURES =
  FEATURE_NAMES minus {age_at_diagnosis, stage_ord, is_metastatic,
  sex_male, smoking_ever} minus all ct_* one-hots (same-site is a hard
  mask instead of a feature).
- Distance: mean of per-feature standardized squared diffs —
  `sqrt(mean((mat[idx]-qv)/std)²)`, std = column std + 1e-9.
  `similarity = 1/(1+dist)`.
- Same-site pool used only when it has ≥k candidates; else all-sites
  (`scope` field tells the UI which happened).
- **Self-exclusion**: query uid removed from the pool — "similar patients"
  means OTHER patients.
- Metadata join keys on `uid` (legacy matrices without the column get a
  verified positional-join check, ≥99% bare-id alignment required).
- Returns twins list (rank, uid, cohort, site, stage, drivers, distance,
  similarity, os_months/status, resistant, tx_agents) + summary
  (n, n_labeled, median_os, failure_rate, KM curve).
- UI slider k=5..20, default 8; API default 25.

## 10. Cohort analytics (`backend/cohort_analytics.py`)

- Filters: cancer_types (any), genes (ALL required), amps, dels,
  tmb_min/max, msi (unstable→spelling family; stable→normalize),
  stage_iv, hrd (explicit False = HRD-negative cohort).
- HRD flag is deliberately TIGHTER than features.HRD_GENES: core
  {BRCA1, BRCA2, PALB2, ATM, RAD51C, RAD51D} mutation OR deep del of
  BRCA1/2/ATM.
- **k-anonymity floor `MIN_COHORT_FOR_STATS = 5`**: n<5 returns counts
  but suppresses failure_rate/median_os/median_tmb/KM/coalterations/
  by_site/by_cohort (`suppressed_small_n: True`) — aggregate answers
  can't re-identify individual patients. n=0 gets the same shape.
- Returns prevalence %, failure rate (labeled subset only), median OS
  (KM), median TMB, KM curve, top-15 co-alteration %, by_site top-8,
  by_cohort.

## 11. Survival (`backend/survival.py`)

Pure-numpy Kaplan-Meier: step function over unique times, at_risk via
sorted-prefix counts, NaN/negative filtered. `median_survival` = first
t where S≤0.5 (None if never crossed). `train_v2.km_curve` is a second
implementation with ≤80-point downsampling for display.

## 12. Flask API (`backend/main.py`, port 5000)

| Endpoint | Notes |
|---|---|
| GET /health | liveness |
| GET /model/info | version, n_training, roc_auc/brier/pr_auc, model meta, auth mode |
| POST /predict | validated clinical input → full prediction |
| POST /predict/batch | {"cases": [...]}, ≤1000, per-case validation |
| POST /cohort/query | aggregate cohort stats (row-level suppressed) |

Security posture:

- `RESISTANCEAI_API_KEY` → `X-API-Key` header required on all data
  endpoints (hmac.compare_digest). Unset = open dev mode.
- Rate limits, per-client sliding 60s window: predict 120/min, batch
  10/min, cohort 30/min (env-overridable, 0 disables). >20k map entries →
  clear (anti-churn). X-Forwarded-For trusted only with
  `RESISTANCEAI_TRUST_PROXY=1`.
- `MAX_CONTENT_LENGTH` 5 MiB (env `RESISTANCEAI_MAX_BODY_BYTES`); 413
  handler returns JSON.
- CORS: `RESISTANCEAI_CORS_ORIGINS` comma list; `*` default = dev only.
- Validation `_validate_clinical_input`: numeric fields reject bools;
  list-of-str fields typed; cna dict str→num; fusions need ≥2 tokens or
  {gene1|gene2} dict with ≥1 non-empty; spectrum dicts numeric;
  spectrum_fractions in [0,1]; stage ∈ {I,II,III,IV,STAGE 1-3,STAGE 4};
  age ∈ (0,130]; ≥1 clinically meaningful field required; unknown fields
  → warnings (echoed in response), unknown cancer_type → "other" warning.
- Errors: 400 with field-level details; 500 is generic (exception text
  stays in logs, never on the wire).
- `flask`/`flask-cors` in requirements; API is optional — the Streamlit
  app uses the predictor in-process.

## 13. Streamlit app (`app.py` + `ui/`)

### Structure

- `app.py` is wiring only: `st.cache_resource` singletons (predictor,
  InstitutionalDB, trial engine, twin engine, cohort engine, queue),
  session state, sidebar, tab dispatch. Missing artifact degrades to the
  landing page + instructions rather than crashing.
- Session keys: `form_data`, `prediction_result`, `case_queue`,
  `ingested_id`, `validation_mode`, `history`.
- Sidebar: Case intake (demo button, NGS JSON upload), Validation mode
  radio (Standard / **Shadow (silent log)**), worklist search+selectbox
  (real corpus uids labeled with cohort, PX-* labeled "demo"), What-if
  analysis (stage slider + TMB input bound to `max(500, cur)` so
  hypermutated POLE cases don't crash the widget).
- "Load a demo patient" prefers a real `_real` queue entry whose site
  contains "Lung" (ALK/EGFR biology exercises everything), else any real
  case, else PX-1109. Landing CTA calls `st.rerun()` explicitly (button
  inside the else-branch needs it).
- Ingest only fires on actual selection change (`ingested_id` guard) —
  prevents re-ingest wiping uploads/perturbations and duplicate
  shadow-log entries. Widget-reset uses `del session_state[key]`
  (assigning to an instantiated widget key raises StreamlitAPIException).

## 14. Honest limitations (say this out loud if asked)

- Interval = ensemble disagreement, not calibrated coverage.
- **Partial label leakage**: CHORD ships only STAGE_HIGHEST_RECORDED
  (max stage over the disease course), so stage_ord/is_metastatic can
  encode post-baseline progression — and is_metastatic is the top
  predictor (ΔAUC ≈ 0.13). Held-out 0.781 AUC is mildly optimistic for
  the pre-treatment task. Mitigation path documented in DATA_SOURCES.md.
- "Resistance" label is a survival/timeline proxy (progression ≤12 mo
  post-first-treatment or death ≤18 mo), not pathology-confirmed.
- Retrospective, single-institution (MSK) population; no prospective or
  multi-site validation.
- CHORD SV fetch is fusion-gene-scoped → sv_count undercounts total SV
  burden vs IMPACT.
- CHORD is CC BY-NC-ND → corpus, derived data AND trained weights can't
  be redistributed; commercial use needs an MSK license. IMPACT is ODbL.
- Audit logs are plain JSON — no real IAM/PHI controls.

## 16. Deployment

- **Local**: `pip install -r requirements.txt` then
  `streamlit run app.py` (UI :8501) and/or `python backend/main.py`
  (API :5000). Tests: `python -m unittest discover -s tests -v`.
- **requirements.txt**: pandas, numpy, scikit-learn >=1.9.1,<1.10
  (pinned to the artifact's training major/minor — pickled HGB/isotonic
  aren't guaranteed loadable across minor versions), streamlit >=1.51
  (width="stretch" API), altair<5, plotly, requests, pyarrow,
  threadpoolctl (explicit dep for serial inference), flask, flask-cors.
- **Dockerfile**: python:3.11-slim, installs reqs, EXPOSE 8501,
  curl healthcheck on `/_stcore/health`, ENTRYPOINT streamlit.
- **`.dockerignore`** excludes raw data, backend/data, the .pkl, and
  runtime ledgers — licensed artifacts must be MOUNTED at runtime:
  `docker run -v /licensed/artifacts:/models -v /licensed/data:/data
  -e RESISTANCEAI_MODEL_DIR=/models -e RESISTANCEAI_DATA_DIR=/data`.
- **Streamlit Community Cloud caveat**: a public app can only read the
  repo → shows landing + PX-* demos; inference/twins/cohort/worklist
  disabled. The real live demo therefore needs a host that mounts the
  artifacts (Railway/Render/Fly/HF/VM). resistanceai.streamlit.app works
  because it's fed the artifacts privately.
- Degradation contract: no MODEL_DIR → inference disabled; no DATA_DIR →
  twins/cohort/worklist disabled but inference still works.
